# F6 Notes -- Review Round 2

The notes of diff review round 2 for card F6, Rate limits
([development-flow.md](https://github.com/huynguyennang-agilityio/tripmate-docs/blob/main/docs/development-flow.md), section 2.4).
Round 2 found one defect, R2-1: on a `signed_in` route the route's own limits were counted before the token check. The product owner chose to count them after it, with the user; it is fixed in `50fae2a`, and the re-run found no defect. The Decision column stays empty until EPIC-11 closes.

| Note | Level | Proposed fix | Priority | Decision |
|------|-------|--------------|----------|----------|
| R2-2: with two counting steps, "every key is counted" and "the longest wait" hold only within one step. A request over the IP limit in step 1 is not counted for the user (nor, on a `signed_in` route, for the route's own limits), and its `Retry-After` is the IP wait alone, so a later window can give a second `429` (`app/platform/rate_limits.py:213`; docstring at `:116`). | Repository | Say in the `enforce` and module docstrings, and in spec 2.2 if the product owner agrees, that the longest wait covers the limits counted in the same step. | Low | |
| R2-3: `_own_limits` does not remove repeats, so a `rate_limit` check reached twice (on the route and as a sub-dependency, or on the router and the route) is counted twice per request and fires at half its limit (`app/platform/rate_limits.py:176`). | Repository | Remove repeats by `id(own)`. Add a unit test with the same check declared twice. | Low | |
| R2-4: `count_limit` takes the `Request`, but spec 2.2 says a module's service counts a key itself, and `service.py` (the public interface, spec 2.1) has no request (`app/platform/rate_limits.py:131`). | Epic | Take the Redis client or a `RateCounter` that `api.py` gets with `Depends` and passes to the service, or record that EPIC-01 counts in `api.py`. | Low | |
| R2-5: "not `public`" is decided by `route_needs_signed_in`, which looks only for the `signed_in` dependency. A capability route whose guard does not depend on `signed_in` would count its own limits before the token check and would not count the user (`app/platform/rate_limits.py:195`). | Epic | In EPIC-02, make capability guards depend on `signed_in`, or make the check mean "every declaration except `public`". Add a unit test with a capability route. | Low | |
