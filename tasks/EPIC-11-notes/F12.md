# F12 Notes -- Review Round 2

The notes of diff review round 2 for card F12, Contract publishing
([development-flow.md](https://github.com/huynguyennang-agilityio/tripmate-docs/blob/main/docs/development-flow.md), section 2.4).
The Decision column stays empty until EPIC-11 closes.

| Note | Level | Proposed fix | Priority | Decision |
|------|-------|--------------|----------|----------|
| `CONTRACTS_TOKEN` is still a repository secret and the environment `contracts` has none, so `publish` reads the repository secret, which any branch workflow can also read; F12-6 does not hold until this changes. | Repository | Before the merge, the product owner adds `CONTRACTS_TOKEN` as a secret of the environment `contracts`, deletes the repository secret, and rotates the token (branch workflows could read it until now); then runs the manual checks F12-4, F12-5, F12-6 on the first merges. | High | |
| README.md ("Fifteen checks are required on `main`") and CLAUDE.md (every CI job is a required check) count `contract` as required, but the branch protection of `main` lists 14 checks without it, so a red `contract` does not block a merge yet. | Repository | The product owner adds `contract` to the required checks of `main` right after the merge. | Medium | |
| The stub pass of the `contract` job has never run in CI, because the app has no stub yet. With two temporary stubs on one path (GET with a bounded query, POST with a body), the CI command failed twice: ST103 (an unreadable body gets FastAPI's undocumented `400`) and ST205 (`405` with `Allow: GET` on a path that also has POST). Both are framework answers, not stub answers. | Epic | F4, when it replaces the framework `400`/`422` with the documented `400 request.invalid`, also documents it on every operation and handles `405`/`Allow`; the first card that adds a stub checks that the stub pass is green in its own CI run. | Medium | |
| `python -m app.platform.contract` runs `app.contract` through `runpy.run_module` by name: a `platform`-to-process dependency that import-linter cannot see, kept only because the locked tests and `tests/INTERFACE.md` fix that command. Its `main(argv)` also ignores `argv` and reads `sys.argv`. | Repository | In a later card that may change the F12 tests, move the command in `tests/INTERFACE.md` and `tests/contract/platform/f12_support.py` to `python -m app.contract`, and drop the `runpy` entry from `app/platform/contract.py`. | Low | |
| `check_examples` follows `$ref` and array `items` only. A response schema built from `anyOf`/`oneOf`/`allOf` (for example an optional or union `response_model`) is reported as having no example even when every branch has one. It fails closed. | Repository | Treat a combined schema as having an example when it has its own, or when every non-null branch has one; add a unit case. | Low | |
| When the contract equals contracts `main` again, the open pull request is closed but `backend/openapi` keeps the old file. If the same contract comes back later, nothing is pushed (equal to the branch) and a new pull request opens from a commit based on an older `main`. | Repository | Delete `backend/openapi` after closing the pull request (`gh pr close --delete-branch`), or compare with the branch only while a pull request from it is open. | Low | |
